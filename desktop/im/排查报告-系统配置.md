# 输入法不弹出 - 系统配置排查报告

## 排查结论

按 README 部署后，**有两个问题**导致输入法不弹出：

| 问题 | 说明 | 处理方式 |
|------|------|----------|
| **1. 插件路径错误** | Wifi 用的是**本地 Qt 5.15.2**，但插件被拷贝到了**系统 Qt5** 的目录 | 见下方「正确部署方式」 |
| **2. 环境变量未设置** | 未设置 `QT_IM_MODULE=im`，Qt 不会加载 im 插件 | 启动前 `export QT_IM_MODULE=im` 或写入 `~/.bashrc` |

---

## 详细分析

### 1. Wifi 使用的是哪个 Qt？

```
Wifi 链接的 Qt 库：
  libQt5Widgets.so.5 => /home/linux/Qt/5.15.2/gcc_64/lib/...
  libQt5Gui.so.5     => /home/linux/Qt/5.15.2/gcc_64/lib/...
  libQt5Core.so.5    => /home/linux/Qt/5.15.2/gcc_64/lib/...
```

结论：**Wifi 使用的是本地安装的 Qt 5.15.2**（`/home/linux/Qt/5.15.2/gcc_64/`），不是系统 apt 的 Qt5。

### 2. Qt 会在哪里找输入法插件？

Qt 会从**当前应用所使用的那套 Qt** 的安装路径下找插件，即：

- **Wifi 会查找**：`/home/linux/Qt/5.15.2/gcc_64/plugins/platforminputcontexts/`
- **不会查找**：`/usr/lib/qt5/plugins/`（那是系统 Qt5 的路径）

README 里写的是「拷贝到 `/usr/lib/qt5/plugins/platforminputcontexts/`」，这对**用系统 Qt5 编译的应用**才有效。你的 Wifi 是用本地 Qt 5.15.2 编译的，所以插件放在系统目录下**不会被加载**。

### 3. 当前系统上实际状态

| 检查项 | 状态 | 说明 |
|--------|------|------|
| `/usr/lib/libcore.so`、`/usr/lib/libui.so` | ✅ 存在 | 按 README 已拷贝 |
| `/usr/lib/qt5/plugins/platforminputcontexts/libIM.so` | ✅ 存在 | 已拷贝，但 Wifi 不会从这里加载 |
| `/home/linux/Qt/5.15.2/gcc_64/plugins/platforminputcontexts/libIM.so` | ❌ 不存在 | 只有 compose、ibus，**没有 im** |
| `/usr/share/pinyin/3rdparty/pinyin/data/dict_pinyin.dat` | ✅ 存在 | 按 README 已拷贝 |
| `QT_IM_MODULE` | ❌ 未设置 | 需要设为 `im` |

## 正确部署方式（针对当前环境）

### 方式一：拷贝插件到本地 Qt 目录（推荐）

```bash
# 把 im 插件拷贝到 Wifi 实际使用的 Qt 的插件目录
sudo cp /home/linux/emb/14-desktop/desktop/im/plugins/platforminputcontexts/libIM.so \
    /home/linux/Qt/5.15.2/gcc_64/plugins/platforminputcontexts/
```

启动 Wifi 前**必须**设置环境变量：

```bash
export QT_IM_MODULE=im
/home/linux/emb/14-desktop/desktop/Wifi/Wifi
```

或一行：

```bash
QT_IM_MODULE=im /home/linux/emb/14-desktop/desktop/Wifi/Wifi
```

### 方式二：用 QT_PLUGIN_PATH 指定插件目录（不拷贝系统目录）

```bash
export QT_IM_MODULE=im
export QT_PLUGIN_PATH=/home/linux/emb/14-desktop/desktop/im/plugins

/home/linux/emb/14-desktop/desktop/Wifi/Wifi
```

这样 Qt 会先到 `desktop/im/plugins` 下找 `platforminputcontexts/libIM.so`，无需拷贝到 Qt 安装目录。

### 持久设置环境变量（可选）

在 `~/.bashrc` 末尾添加：

```bash
# 使用 im 软键盘
export QT_IM_MODULE=im
# 若用方式二，可一并添加：
# export QT_PLUGIN_PATH=/home/linux/emb/14-desktop/desktop/im/plugins
```

然后执行 `source ~/.bashrc` 或重新打开终端。

---

## 一键启动脚本（推荐）

项目根目录已提供 `run_wifi_with_im.sh`，会自动设置 `QT_IM_MODULE` 和 `QT_PLUGIN_PATH`：

```bash
cd /home/linux/emb/14-desktop
chmod +x run_wifi_with_im.sh
./run_wifi_with_im.sh
```

无需再拷贝插件到 Qt 目录，也无需每次手动 export。

---

## 总结

| 原因 | 处理 |
|------|------|
| 插件在 `/usr/lib/qt5/...`，而 Wifi 用本地 Qt 5.15.2，不会去那里加载 | 拷贝到 `/home/linux/Qt/5.15.2/gcc_64/plugins/platforminputcontexts/` 或设置 `QT_PLUGIN_PATH=desktop/im/plugins` |
| 未设置 `QT_IM_MODULE=im` | 启动前 `export QT_IM_MODULE=im` 或使用 `run_wifi_with_im.sh` |

按上述任一种方式修正后，再运行 Wifi，点击输入框应能弹出 im 软键盘。
